# The `display_driver` contract on the STM32MP135F-DK

`python/linux/display_driver.py` implements version 1 of the `display_driver` contract
(`CONTRACT = 1`) defined in `docs/display-driver.md` of
[mpy-lvgl-boards](https://github.com/Copper-And-Code/mpy-lvgl-boards): the same names (`WIDTH`,
`HEIGHT`, `BUFFERS`, `PERIOD_MS`, `indev`, `start()`, `stop()`, `running()`, `backlight()`) as on the
MCU boards, so code generated by Copper and Code Studio does not know that it runs on Linux.

## Linux backend

The Linux driver uses a DRM dumb buffer and the Goodix event device. It has one full-screen RGB565
buffer in DIRECT mode and exposes the measured panel resolution and stride through `linuxfb.open()`.
The backlight maps 0–100% to the kernel sysfs brightness range. `stop()` waits for the LVGL thread to
finish; calling it from an LVGL callback in that same thread does not wait for itself. `start()`
cannot overlap an earlier service that is still stopping.

LVGL is served by a thread, and the variant enables the MicroPython GIL so that this thread and
`main.py` or the REPL never call LVGL at the same time (see `docs/stm32mp135f-dk.md`).

Both this driver and `touch_evdev.py` are frozen. Keep `.frozen` at the start of `MICROPYPATH` in the
REPL services. Before a soft-reset `execve`, `mpyrepl` closes inherited descriptors above stderr so
that DRM and input devices do not leak across restarts.

## Tests

`tests/hil/t11_mp135_display.py` checks the physical DRM panel, touch, backlight and
`stop()`/`start()`; `tests/hil/t12_mp135_performance.py` measures full-screen rendering throughput.
